## T-01 · 数据写入并发（P1）

- **现状**：`db.json` 整文件读改写；两台电脑同一分钟写入时，后写的整文件覆盖前写的字段
- **做法**：服务端加「写队列 + 原子替换」（temp 文件 + `rename`），PATCH 按记录粒度合并再落盘
- **验收**：并发 20 次 PATCH（不同记录/同记录不同字段）后字段全在；写盘期间无半截 JSON
- **来源**：`DEVELOPMENT.md` 数据可靠性项 / `docs/walkthrough/pitfalls-checklist.md` G-13

## T-02 · 无障碍第二批（P2）

- **现状**：卡片能用 Tab + Enter 打开，但**拖拽排序仍只能鼠标**；弹窗关闭后焦点不回填；抽屉内无焦点陷阱
- **做法**：列头/卡片菜单加「上移 / 下移」；`closeDrawer` 记录触发元素并 `focus()` 回去；抽屉内 Tab 在首尾循环
- **验收**：`audit_a11y` 扩 3 项——键盘移动改变顺序并落库、关闭后焦点回到原卡片、Tab 循环不逃出弹窗
- **来源**：`docs/ARCHITECTURE.md` P3 行 / 走查残余风险

## T-03 · 渲染路径不再读布局（P2）

- **现状**：`fitGiNum()`、`paintAccPanel()` 在渲染过程中调 `getBoundingClientRect`（全文 17 处），存在读写交织
- **做法**：先批量读尺寸 → 再统一计算 → 最后一次性写样式；或用 `ResizeObserver` 缓存尺寸
- **验收**：视觉零变化（`audit_gh_header` 31 项 + `audit_responsive` 24 项全绿），且渲染函数内不再出现布局读
- **来源**：走查 P-18 / G-23

## T-04 · 长列表渲染（P2）

- **现状**：任务卡与仓库卡每次全量重建 DOM；卡片很多时滚动与输入会掉帧
- **做法**：列内分批渲染（首屏 N 张 + 滚动加载），仓库卡按需展开（已有「查看全部」可复用）
- **验收**：造 1000 张卡的数据脚本下，首屏渲染耗时记录基线并下降；`mk_v16` 列数断言不受影响
- **来源**：走查 P-19 / G-22

## T-05 · 契约一致性自动校验（P2）

- **现状**：字段契约有 5 处（`SCHEMAS` / `REQUIRED·ENUMS` / `/api/contract.json` / `contract.md` / 页面 `AI_CONTRACT`），靠人记同步
- **做法**：加一个脚本比对 5 处字段名与枚举，不一致直接报错，并接进 `run_all.py`
- **验收**：故意漏改一处 → 测试红；全绿时 5 处字段集合完全相同
- **来源**：`docs/REFACTOR-PLAN.md` §2.4 / G-16

## T-06 · 备份入口接到界面（P3）

- **现状**：服务端已有 `/api/backup`（列表 + 恢复，恢复前先备份当前库），但界面没有入口
- **做法**：顶栏「更多」菜单加「备份 / 恢复」，恢复走确认框并展示备份时间
- **验收**：`audit_write_paths` 增加「恢复后数据与备份时刻一致」断言
- **来源**：`DEVELOPMENT.md` 可靠性清单

## T-07 · GitHub 记录体积治理（P3）

- **现状**：`github` 表每条同步记录一行，长期只增不减；开发强度/日历按全量扫描
- **做法**：提供「导出 CSV」+「按年归档（移到归档文件）」；归档不改任务关联
- **验收**：导出文件可被 Excel 打开；归档后 KPI 与强度只统计未归档部分且有说明
- **来源**：规模基线 / G-22

## T-08 · 多端刷新（P3）

- **现状**：另一台电脑的改动要手动刷新才可见（无实时推送）
- **做法**：可选 30s 轮询（页面隐藏时暂停，失败退避），默认关闭
- **验收**：两个实例（两个端口）互看；断网时错误不刷屏
- **来源**：走查 S-10 N/A 的补记 / `ARCHITECTURE.md` 已知限制
