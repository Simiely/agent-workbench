# 程序设计常见问题清单（调研 + 本项目核验）

> 用途：走查时逐条对照。**每条都给「本项目是否中招」的判定与证据**，避免只凭印象。
> 判定口径：❌ 中招 / ⚠️ 部分中招 / ✅ 未中招 / — 不适用。

## 一、数据与真相

| # | 坑 | 表现 | 本项目核验 |
|---|---|---|---|
| G-01 | **同一事实存在多份副本** | 改一处、另一处没改，界面与库不一致 | ❌ 电脑身份有三份：machines 名 / accounts 所属电脑 / github 电脑（见 F-01/F-03） |
| G-02 | **派生值被客户端缓存** | 服务端已重算，前端仍用旧缓存 | ❌ 改名/删机后前端不重拉 accounts（F-02） |
| G-03 | **级联更新遗漏** | 改名/删除只处理了主表 | ❌ 改名不清 GitHub 筛选；删机不重拉账号（F-02/F-03） |
| G-04 | **删除后留孤儿** | 外键指向已删记录 | ✅ 任务落孤儿列；服务端删机连带删账号（server.mjs:739）；账号删当前自动顺延（735） |
| G-05 | **默认值/空值语义混淆** | `''`、`未登录`、缺失三种混用 | ✅ `未登录`/空串都翻译成「无当前」，不写脏账号（server.mjs:applyMachineAccountWrite） |

## 二、写入与失败

| # | 坑 | 表现 | 本项目核验 |
|---|---|---|---|
| G-06 | **先改内存、后写库，失败不回滚** | 失败后界面显示的是没落库的假状态 | ❌ renameMachine 先改任务名，失败不回滚（F-04）；其余写点均回滚重拉 |
| G-07 | **批量操作「部分成功」按全成功上报** | toast 说删了 10 个，实际 8 个 | ❌ 批量更新/删除单条失败只 console（F-05） |
| G-08 | **多步写入无事务** | 顺序持久化逐条 PATCH，中途失败留半套 | ⚠️ 列/卡片排序逐条写、失败静默（F-06） |
| G-09 | **错误被吞（只 console.error）** | 用户看不到失败，以为成功 | ⚠️ schema 加载失败静默（F-07）；「最后确认」失败静默（影响极小） |
| G-10 | **失败提示没有下一步** | 只说「失败」，不说怎么办 | ⚠️ 多处 toast 只说失败；本轮统一补「正在回滚/重新拉取」语义（已有部分） |

## 三、并发与幂等

| # | 坑 | 表现 | 本项目核验 |
|---|---|---|---|
| G-11 | **全量覆盖式写入** | 两端同时编辑互相覆盖 | ✅ 表单保存只提交真正变化的字段（stripUnchanged）；PATCH 只校验本次字段 |
| G-12 | **状态机不变量无人守** | 同池出现两个「当前」 | ✅ 客户端关同池其他 + 服务端 markCurrent 权威兜底 + ensureCurrent 顺延 |
| G-13 | **重复提交** | 连点两次产生两条 | ✅ 保存按钮 disabled；服务端唯一约束（机器名/同机同平台账号名）兜底；双击新增会有一条 400（⚪ 提示略突兀） |
| G-14 | **多端无刷新** | 另一端改动看不到 | — 设计如此（无实时推送，刷新即最新）；文档已登记 |

## 四、校验与契约

| # | 坑 | 表现 | 本项目核验 |
|---|---|---|---|
| G-15 | **前端校验当全部校验** | AI/直连 API 绕过表单写脏数据 | ✅ 服务端 REQUIRED/ENUMS + 唯一性；PATCH 只校验本次字段（历史脏记录不被永久拒写） |
| G-16 | **契约五处不同步** | SCHEMAS / contract.json / contract.md / AI_CONTRACT / REQUIRED | ✅ 有同步清单（REFACTOR-PLAN §2.4）；本轮未改字段 |

| G-18 | **损坏数据被静默覆盖** | JSON 解析失败当空库 | ✅ 另存 `db.corrupt-<时间>` + /health 暴露 |

## 五、时间、边界与规模

| # | 坑 | 表现 | 本项目核验 |

- 部分中招、登记即可：G-22 / G-23 / G-27 / G-28
- 做得好的：G-04 / G-05 / G-11 / G-12 / G-15 / G-17 / G-18 / G-24 / G-25 / G-26
