## 三条贯穿性教训

### 1. 「显示成功但数据不对」比报错更危险

P-G、E-10、E-9 都是这类：界面显示「新增 N 条」，实际数据丢了或多了。用户无从察觉。
后来专门列了三类排查项写进 AGENTS.md。

### 2. 报错必须指向真因，且要「可执行」

| 反例 | 问题 |
|---|---|
| 「请先写一个「## 电脑（新建）」块」 | 没说那块长什么样 |
| 「认不出的字段：进度」 | 真因是动作写错（同步不支持更新） |

更硬的约束：**报错里提到的任何写法，必须同时存在于提示词里**，否则就是死锁
（v1.7.0 精减掉电脑块后正中这条）。

### 3. 契约要双向核对

本项目出过两次漂移：`databaseId`/`db`、账号语义。第五轮系统对了一遍：

- 提示词 → 解析器：**零漂移**
- 解析器 → 提示词：账号块 5 个字段没教 → 降级为辅助块并补全
