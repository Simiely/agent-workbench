# 注意事项 · 会踩的坑与怎么避免

> 按「踩了会怎样」分级。🔴 = 会丢数据或静默写错，务必先看。
> 每条都写了**怎么避免**，不是只描述现象。
> 字段口径见 [数据字典.md](数据字典.md)，维护链路见 [维护指南.md](维护指南.md)。

---

## 🔴 一、导入 CSV 是「整表替换」，不是追加

**现象**：库里已有 20 条任务，导入一个只有 3 条的 `awb-tasks.csv`，
结果**只剩那 3 条**，原来的 20 条没了。

代码里就是 `db[t] = recs;` 一行赋值——整表替换，不合并、不追加。

**怎么避免**：

1. **导入前先导出备份**（顶栏「CSV」→ 导出 4 个 CSV）
2. 想"加几条"，正确做法是：**先导出 → 在 CSV 里把新行加上 → 再整体导入**
3. 只导入某一张表，不影响其它三张表（覆盖是**按表**的，不是全库）

> 导出会自动生成 4 个文件，文件名 `awb-tasks.csv` 这种。
> 覆盖只对导入的那几张表生效。

## 🔴 二、换电脑 / 换浏览器 / 清缓存，数据不会跟随

**现象**：新电脑打开资料库版，四张表是空的。

数据存在**浏览器 localStorage** 里，跟「哪台电脑 + 哪个浏览器」绑定，
不在云端、不跨设备。

**怎么避免**：

| 场景 | 做法 |
|---|---|
| 换电脑 / 换浏览器 | 旧端导出 4 个 CSV → 拷过去 → 新端导入 |
| 长期留档 / 多端同步 | **把 CSV 放进 WorkBuddy 资料库**——CSV 在云端，那才是持久化 |
| 清缓存前 | 先导出，别指望"清完还在" |

**判断口诀**：**数据跟着 CSV 走，不跟着浏览器走。**

---

## 🔴 三、待办不照抄原文，会追加出重复项

**现象**：待办 4 条变 5 条，多出一条几乎一样的。

更新任务时，待办**按原文匹配**已有项改勾选，**匹配不上就追加**。

| | 内容 |
|---|---|
| 原文 | `[ ] 沙箱验证后推 remote` |
| AI 写的 | `[x] 沙箱验证后推送 remote`（多一个「送」字） |
| 结果 | 匹配不上 → 追加 → 4 条变 5 条 |

**怎么避免**：

- 「复制提示词」给的现状骨架里**带待办原文**，让 AI 照抄
- **不需要重抄整份待办**——只写本次动过的那几条，没写的原样不动
- 导入前看预览，确认写的是「勾选已有 N 条」而不是「新增 M 条」

---

## 🔴 四、WB/TRAE 账号 ≠ GitHub 账号

**现象**：同步记录的「账号」列被填成 `WB-主号` 这种登录账号，
**服务端不校验，静默写脏**，事后很难发现。

| 账号类型 | 用在哪 |
|---|---|
| **WorkBuddy / TRAE 登录账号** | 机器登录态（`accounts` 表，机器表上是派生显示） |
| **GitHub 账号** | 同步记录的 `GitHub账号` 列（库里多是 `Simiely` 这种） |

**怎么避免**：写同步记录时，账号只填 GitHub 账号名。
提示词里两类账号是**分开列的**，别混。

---

## 🟡 五、清空不可撤销

「CSV」面板的「清空全部数据」会清空四张表，**没有回收站**。

**怎么避免**：清空前先导出备份（面板会弹确认，但确认≠备份）。

---

## 🟡 六、资料库版 HTML 是生成物，别手改

`agent-workbench-资料库版.html` 是由 `public/index.html` + `server.mjs` 拼出来的。
手改了也会被下次 `build.mjs` 覆盖掉，白改。

**怎么避免**：改 `public/index.html` 或 `server.mjs`，然后跑：

```bash
node library/tools/build.mjs
```

---

## 🟡 七、CI 还没生效，目前靠手动

`.github/workflows/library-align.yml` 在本地仓库里是好的，但**没推到远端**——
GitHub 要求写 `.github/workflows/` 的 token 具备 `workflow` scope，当前 token 只有 `repo`。

**不影响使用**，只是少了个自动提醒。改了主项目后手动跑：

```bash
node library/tools/build.mjs    # 重新生成
node library/tools/check.mjs    # 对齐校验
```

换电脑 clone 下来也不会有 CI 目录，同样手动跑这两条。

## 🟡 八、CSV 编码必须是 UTF-8

**现象**：用 Excel 打开 CSV 再保存，中文变乱码（Excel 默认存 GBK）。

**怎么避免**：

- 导出的是 **UTF-8 BOM** 格式，Excel 双击打开正常
- 要编辑就用**记事本 / VS Code**，别用 Excel 直接保存
- 万一乱码：文件另存时手动选 UTF-8 编码

---

## 🟡 九、CSV 文件名要含表名

导入**按文件名认表**，靠文件名里含 `tasks` / `machines` / `accounts` / `github`。

**怎么避免**：改名别把这串英文改没了。
`awb-tasks.csv` ✅ ｜ `任务台账.csv` ❌（认不出，会提示"认不出是哪张表"）

## ⚪ 十、机器表的账号列不要建

`machines` 的 `WorkBuddy账号` / `TRAE账号` 是**派生只读**，
由 `accounts` 表「当前=true」的那条算出，存储里不留第二份。

**怎么避免**：CSV 里没有这两列（所以是 5 列不是 7 列）；
接资料库表格时也别给它们建列。改登录态去 `accounts` 表切「当前」。

---

## ⚪ 十一、定位已有卡片用 id，不用序号

批量导入定位已有任务时，用卡片 id（`#t1`、`#10a20b7db2f2`）。

**为什么**：早期版本用过位置序号，实测在列表中间插入一张卡后，
后面所有序号**全部后移一位**——AI 回写的 `编号：1` 就打到另一张卡上，
而且预览里不细看标题发现不了。**静默数据污染**，已改用 id。

**怎么避免**：id 稳定不变；卡片被删则直接报错，不会误写别人。

## ⚪ 十二、响应式：中间态已删，改断点要 CSS + JS 同步

≤1100px 直接进手机形态（T-bar 一次一页），**700~1100px 之间不再有「上下堆叠」过渡态**。

改这个断点时，**三处必须同时动**，漏一处就出半吊子状态：

| # | 位置 | 内容 |
|---|---|---|
| 1 | 手机形态 `@media` | 宽度断点（现 1100px）+ 高度/扁平比分支 |
| 2 | 手机形态的 `.view` | **`width: auto !important`** |
| 3 | `bindMobilePages()` 的 `matchMedia` | 字符串要和第 1 处**逐字一致** |

第 2 条最容易漏：删上下堆叠块时它跟着被删，而手机形态的 `.view` 只写了
`padding / overflow / border-radius`，没重置 width —— 左右分屏的
`#viewBoard { width: 58% }` 会继续生效，单栏只占 29%，右侧空一大片。

漏第 3 条则会出现「JS 切了页、CSS 没隐藏另一页」。

## ⚪ 十三、用户导出的 CSV 不要提交进仓库

导出的 CSV 里是**个人数据**（任务、路径、账号）。仓库里那 4 个是**空模板**，只有表头。

**怎么避免**：提交前看一眼文件内容；建议 `.gitignore` 排除导出目录。
