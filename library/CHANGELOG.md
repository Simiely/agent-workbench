## [1.0.0] - 2026-11-02

资料包首次成体系落地。此前 `library/` 只是一个文件夹，没有维护机制——
HTML 是手工拼的、生成脚本不在仓库里，**改了主项目根本没法重新生成**。

### 新增

- **生成脚本** `library/tools/build.mjs`
  - 一条命令重新生成资料库版 HTML + 4 个 CSV 模板
  - 字段清单**从 `server.mjs` 的 SCHEMAS 派生**，不硬编码——主项目加字段，CSV 模板自动跟着变
  - 版本号从 `package.json` 读
- **对齐校验脚本** `library/tools/check.mjs`
  - 比对 5 类一致性：CSV 表头 / HTML 内嵌字段 / 版本号 / 枚举 / 提示词数据形状
  - 退出码非 0，可接 CI
  - 做过反向验证：故意删列、改错枚举、多写派生字段，都能抓到（不是恒绿的摆设）
- **维护文档** `维护指南.md`
  - 讲清资料库版是**生成物**还是**真源**，改了什么要动哪里
  - 加字段的完整清单（6 步，最容易漏的第 3 步是补数据字典）
  - 谁能手改、谁不能（一张表）
- **数据字典** `数据字典.md`
  - 四张表全部字段：类型 / 必填 / 说明 / 坑
  - 重点写了两个会写脏数据的坑：待办原文匹配、WB/TRAE 账号 ≠ GitHub 账号

### 变更

- 资料库版 HTML 顶部的数据源适配说明改为**生成时动态写入**（原来手写，会过期）
- CSV 列顺序改为跟随 SCHEMAS 原生顺序（导入按列名对齐，顺序无关）
  - 注：`tasks` 的 `所在电脑` 从第 5 位移到第 10 位

### 修复

- CSV 解析器：字段**中间**的引号被误当包裹符，手工写的 `标题 "重点"` 会被吞掉引号。
  改成只有字段起始处的引号才算包裹符

## [0.1.0] - 2026-11-02

资料包初版：单文件 HTML（空壳四表）+ 4 个 CSV 模板 +
`README.md` / `接数据源提示词.md` / `示例导入文本.md` / `示例-走查导入内容.txt`。

HTML 是手工拼装的，生成脚本留在沙盒里没进仓库——**这是 1.0.0 要解决的主要问题**。
