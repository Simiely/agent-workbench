# 数据字典

> 四张表全部字段的口径说明。**导入 CSV 前先看这份**，写错会被拦下。
> **先看完 [注意事项.md](注意事项.md) 再用**——导入是整表替换、待办要照抄原文，
> 这两条不知道容易写坏数据。
> 真源是 `server.mjs` 的 SCHEMAS，本文件是给人和 AI 看的说明；
> 两者不一致时**以 SCHEMAS 为准**，并跑 `node library/tools/check.mjs` 确认。

## 通用口径

| 概念 | 说明 |
|---|---|
| `_id` | 卡片 id，页面自动生成（如 `t1`、`10a20b7db2f2`）。CSV 里可留空，导入后由页面补。**定位已有卡片用它**，不要用位置序号 |
| `date` | 写 `2026-11-02` 或 `2026-11-02 14:30`。不写则由服务端补当前时间 |
| `checkbox` | CSV 里写「是 / 否」或 `true / false` 均可 |
| `number` | 排序值，服务端按时间排，一般不填 |

**一份记录 = 一件事**：一个任务 = 一个可交付的活；一条同步 = 一个版本的一次同步。

## 一、tasks · 任务台账（CSV: `awb-tasks.csv`，11 列）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `_id` | id | — | 定位用 |
| `任务标题` | text | ✅ | 不能与已有任务重名（重名会被拦下，避免造出两张同名卡） |
| `状态` | select | ✅ | 进行中 / 已完成 |
| `优先级` | select | ✅ | P0 / P1 / P2 |
| `所在电脑` | text | ✅ | 必须是已登记的机器名，写别的会被拦下 |
| `目录` | text | — | 项目路径。判断"是不是同一个项目"的线索，比标题准 |
| `进度` | text | — | **一句话说清本次做了什么**。卡片上唯一显示进展的地方，建议每块都写 |
| `待办` | text | — | 多行，行首 `[x]`（已完成）或 `[ ]`（未完成） |
| `交接内容` | text | — | 下一步要注意什么 / 回滚点 |
| `更新时间` | date | — | 不写补此刻 |
| `排序` | number | — | 一般不管 |

### ⚠️ 待办字段最大的坑

更新任务时，待办**按原文匹配**已有项改勾选，匹配不上的会**追加到末尾**。

所以「复制提示词」给的现状骨架里带了待办原文，**请照抄**。
改一个字就会多出一条几乎一样的重复项：

| | 内容 |
|---|---|
| 原文 | `[ ] 沙箱验证后推 remote` |
| 改写 | `[x] 沙箱验证后推送 remote`（多一个「送」字） |
| 结果 | 匹配不上 → 追加 → 待办 4 条变 5 条 |

**不需要重抄整份待办**——只写本次动过的那几条就行，没写的原样不动。

## 二、machines · 机器登录态（CSV: `awb-machines.csv`，5 列）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `_id` | id | — | 定位用 |
| `机器名` | text | ✅ | 不能重名 |
| `位置` | text | — | 如「书房」「Office」，纯标注 |
| `最后确认` | date | — | |
| `排序` | number | — | |

### ⚠️ 派生字段不在 CSV 里

页面上的 **`WorkBuddy账号` / `TRAE账号` 是派生只读值**，
由 `accounts` 表里「当前=true」的那条实时算出，**存储里不留第二份**。

- CSV 里没有这两列（所以是 5 列不是 7 列）
- 接表格时不要给它们建列
- 要改登录态：去 accounts 表切换「当前」，不是直接写机器表

## 三、accounts · 登录账号（CSV: `awb-accounts.csv`，8 列）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `_id` | id | — | 定位用 |
| `账号名` | text | ✅ | |
| `平台` | select | ✅ | WorkBuddy / TRAE |
| `所属电脑` | text | ✅ | 必须是已登记的机器名 |
| `当前` | checkbox | — | **一台电脑 × 一个平台，至多一条为「是」**。设为「是」时同组其它条自动置否 |
| `备注` | text | — | |
| `最后确认` | date | — | |
| `排序` | number | — | |

⚠️ 这里的账号是 **WorkBuddy / TRAE 登录账号**，
**不是 GitHub 账号**——同步记录的「账号」列要填 GitHub 账号（如 `Simiely`）。
这两类账号混填是本项目踩过的坑（服务端不校验，会静默写脏）。

## 四、github · GitHub 同步记录（CSV: `awb-github.csv`，10 列）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `_id` | id | — | 定位用 |
| `同步时间` | date | — | 不写补此刻 |
| `电脑` | text | ✅ | 必须是已登记的机器名 |
| `GitHub账号` | text | — | GitHub 账号名（如 `Simiely`），**不是** WB/TRAE 登录账号 |
| `仓库` | text | ✅ | 形如 `Simiely/ae-tools` |
| `内容` | text | — | 一句话，这次同步了什么 |
| `同步版本` | text | — | 形如 `v1.5.9`。一份同步 = 一个版本的一次同步 |
| `是否同步` | select | — | 已同步 / 未同步 |
| `仓库归档` | checkbox | — | **仓库级属性**，勾上则整个仓库归档 |
| `仓库置顶` | checkbox | — | **仓库级属性**，勾上则整个仓库置顶 |

> 同步记录**每次都是新增一条**，没有「更新」——一个版本一次同步，
> 想改历史记录请直接改 CSV。

---

## 必填汇总

| 表 | 必填字段 |
|---|---|
| tasks | 任务标题、状态、优先级、所在电脑 |
| machines | 机器名 |
| accounts | 账号名、平台、所属电脑 |
| github | 电脑、仓库 |

必填空、枚举越界、机器名/任务标题重名，导入时都会**拦下并说明原因**，不会静默写脏。
